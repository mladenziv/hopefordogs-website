# Project Notes

## Deployment

This site is deployed from GitHub (via cPanel auto-deploy to GoDaddy). Local file changes are NOT visible until committed and pushed to `main`. Always commit and push after making changes so they can be tested on the live site.

## Development Rules

- **Copy before innovating**: When adding a feature that's basically the same as something that already works (e.g. Facebook fetch for stories = same as dogs), copy the working code first and adapt it minimally. Don't rewrite or "improve" the patterns — GoDaddy's PHP has strict PCRE limits and things that look fine can crash on large input. Get it working first with proven code, then iterate.
- **Trust what already works**: If something is already working elsewhere in the codebase (e.g. the dogs form pulls multiple photos from Facebook), don't assume it won't work for the new feature. Test the existing code path first before concluding there's a limitation. The API was already returning multiple images — the problem was broken PHP, not a Facebook limitation.
- **Verify before pushing**: Always test PHP changes locally against real data before committing. For API endpoints, fetch the actual HTML, run the extraction logic, and confirm valid JSON output. Never push and hope — verify it works first.
- **Debug empty JSON responses by testing each step**: When PHP returns empty responses ("Unexpected end of JSON input"), the cause is usually `json_encode()` returning `false` due to invalid UTF-8. Debug approach: (1) curl the Facebook URL to get the raw HTML, (2) test each regex pattern individually with GoDaddy-like PCRE limits (`pcre.backtrack_limit=100000`), (3) check `preg_last_error()` for each — error 4 = bad UTF-8, error 2 = backtrack limit, (4) verify `json_encode()` succeeds on the final output. Root cause of the emoji crash: Facebook JSON uses surrogate pairs (`\ud83e\udde1`) for emoji — must decode pairs together, not each `\uXXXX` individually.
- The beheer app is a compiled React bundle — all JS changes are search-and-replace edits on the minified `beheer/assets/index-D72IbPDC.js`.
- **Blog editor = Quill (`beheer-editor.js`, site root, loaded via `../beheer-editor.js` in beheer/index.html).** The bundle's bare contentEditable was too buggy (dividers, toggling, Enter) so we replaced it with Quill (loaded from jsdelivr CDN in beheer/index.html: quill.snow.css + quill.js). `beheer-editor.js` finds the bundle's `.prose[contenteditable]` via a MutationObserver, mounts Quill in a `.h4d-quill` div beside it, hides the original editor + its custom toolbar, and BRIDGES Quill back into React: on `text-change` it sets `el.innerHTML = quill.getSemanticHTML()` (with `&nbsp;`→space) and dispatches a native `input` event — which the bundle's own listener uses to update React state and save. If Quill fails to load, nothing is hidden and the original editor still works (graceful fallback). Quill's toolbar: H2/H3/normal, bold, italic, ordered/bullet list, blockquote, link, clear. Editor styling (`.h4d-quill .ql-editor …`) matching the live blog lives in `beheer/assets/index-NmunAMGN.css`.
- **Rich ↔ Markdown toggle (`beheer-editor.js`):** a `.h4d-mdtoggle` button in a `.h4d-modebar` above the Quill toolbar swaps the rich editor for a `.h4d-md` textarea. Conversion is SELF-CONTAINED — no CDN (an earlier marked/turndown CDN version silently fell back to raw text when the CDN didn't load, so the user saw literal markdown). `mdToHTML()`/`htmlToMd()` inside beheer-editor.js cover the blog's subset: h1–h6, **bold**, *italic*, `- `/`1. ` lists, `> ` quotes, `[t](u)` links, inline `code`. MD→Rich = `mdToHTML` → `quill.clipboard.dangerouslyPasteHTML` → the `input`-event bridge → state. A `text-change` guard (`if(mode!=='rich')return`) stops hidden-Quill from clobbering state in MD mode, and the textarea's `input` keeps state synced so Save works in either mode. Note: `---`/`<hr>` doesn't survive (Quill core has no hr blot) — fine, the blog has no dividers. Workflow: toggle to MD → copy out → ChatGPT fixes formatting → paste back → toggle to Rich → save. Tell authors to use `##`/`###` for section headings (`#`→h1 duplicates the page title).
- **Blog drafts + scheduled publishing (no schema change — `published_at` is the source of truth):** `null` = draft (hidden), future timestamp = scheduled (hidden until due), past = live. Public side filters on it: `nieuws.html` query uses `published_at=lte.<encodeURIComponent(new Date().toISOString())>` (one `lte` excludes both null and future); `post.html` `loadPost` gates with `isLive = post.published_at && new Date(post.published_at) <= new Date()` and `showError()` unless live — `?preview=1` bypasses (admin review; not a security control, anon can read the table). Auto-release needs NO cron: pages query on each load, so a scheduled post appears on the next load after its time. In the beheer bundle (`index-D72IbPDC.js`), the save fn is `w=async(asDraft)=>` with `published_at:asDraft?null:(h.published_at?…:null)`; the dialog footer has **Concept** (`w(!0)`) + **Opslaan** (`w(!1)`) buttons (mirrors the dogs editor's Concept pattern); the posts list row shows a status label (`Concept` / `Gepland: <date>` amber via inline `color:#b45309`, else the date). Admin fetch orders `published_at` DESC so null drafts surface at the top. NOTE: the 4 legacy `DRAFT …`-titled posts have past dates and are still public — convert each in beheer (drop the prefix, click Concept or set a real date).
- **Dog photo cropper (beheer):** the dog-photo crop dialog uses Cropper.js (`new window.Cropper(el,{aspectRatio:4/3,viewMode:1,autoCropArea:0.8,responsive:!0})` in `index-D72IbPDC.js`) locked to **4/3** to match how dog photos display (`.dog-card-img` height:320px≈4/3 on honden.html, and `hond.html`/skeleton use `aspect-ratio:4/3`). This cropper is dog-only (source is a `dog_photos` row `cP.photo_url`); blog/social use plain string `photo_url` and are not cropped here.
- **clean-on-load vs clean-on-save:** the bundle's editor `el.innerHTML=...` uses `window.h4dCleanBlogHTML` (aggressive: fixes old messy pasted content before Quill loads it); the Supabase upsert `content:` uses `window.h4dStripHTML` (light: only strip style/class + unwrap span/font — Quill output is already clean, so we must NOT re-run the aggressive heading/bullet heuristics on save).
- **Blog post editor (beheer):** the post `content` editor is a plain `contentEditable` + `document.execCommand`. Enhancements live as 3 search-replace edits in the bundle: (1) a `paste` listener on the editor ref that forces plain-text paste (`execCommand("insertText")`), (2) extra toolbar buttons after the Italic button (`insertUnorderedList`/`insertOrderedList`/`formatBlock,blockquote`/`createLink`/`insertHorizontalRule`), (3) clean-on-save (strip `[style]`/`[class]` + unwrap `span,font`) wrapped around `content:h.content` in the Supabase upsert. If the bundle is ever re-exported these break — re-apply against the new minified names.
- **Blog content normalizer (`blog-normalize.js`, site root):** ONE shared cleaner (`window.h4dCleanBlog(el)` / `window.h4dCleanBlogHTML(str)`) used by BOTH `post.html` (on render) and the beheer editor (on load + on save), so the live page and the editor show identical clean formatting. It strips inline styles, wraps bare text runs in `<p>`, converts literal `•` bullet paragraphs into real `<ul>`, drops spacer `<p>` (the "empty rows"), `<b>`→`<strong>`, promotes bold-only `<p>`→`<h2>` (drops the title-duplicate first line), strips `*`/`**` heading markers, and `--`→`—`. post.html loads it via `blog-normalize.js`; beheer loads it via `../blog-normalize.js` (added before the module in `beheer/index.html`) and the bundle wires it into `el.innerHTML=...` (clean-on-load) and the `content:` field of the Supabase upsert (clean-on-save). The `posts` table is Auth+RLS write-protected (anon cannot write — confirmed via a 0-row `return=representation` PATCH), so there's no DB migration: cleanup is on render + on editor load/save.
- `.post-content` CSS in `post.html` is the editorial type system; the editor mirrors it via `.prose …` rules appended to `beheer/assets/index-NmunAMGN.css`.
